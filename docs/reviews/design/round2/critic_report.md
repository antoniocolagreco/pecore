## Blockers

- **`egm-design-1-1` · Approval can cover a different tree from the one delivered.** A workdir can change between diff capture and checks. The checks can pass on the new tree while the human sees the earlier diff. Record the tree shown in review, verify that the approval and required checks cover what is delivered, and define any patch-based exception after a rebase. Describe `changesFiles: false` as detection and restoration of changes to the computed tree. Ignored files can still affect checks. Related finding `egm-style-1-6`. [Recipe gates](docs/design.md#L376) · [Artifacts](docs/design.md#L415) · [Content state](docs/design.md#L530)
- **`egm-design-1-2` · Interrupted rebases can alter another job’s stash.** Job worktrees share `refs/stash`. The rebase uses the stash and interruption recovery resets the shared ref. Keep rollback checkpoints under job ownership and restore only the interrupted job’s state. [Rebase](docs/design.md#L407) · [Rollback and shared repo](docs/design.md#L540)
- **`egm-design-1-3` · The Compose safety check leaves the host boundary undefined.** The runner invokes repository-supplied Compose configuration as the app user. The listed forbidden keys cover only part of the configuration surface. Define the supported service configuration, validate the fully resolved inputs, and confirm exactly what the runtime receives. [Job services](docs/design.md#L576) · [Host access risk](docs/design.md#L825)

## Major findings

- **`egm-design-1-4` · Protected mode shares access across harness accounts.** Every protected harness and the orchestrator run under `pecore-agent`. Separate config directories select logins. The OS permissions of that shared user determine access, including access to other protected harness logins. State that boundary wherever the document describes credential exposure. Describe PeCore as having no provider credential store and qualify file access by OS permissions. Related findings `egm-structural-1-4` and `egm-style-1-4`. [Harness login location](docs/design.md#L439) · [Protected mode](docs/design.md#L725) · [Credential risk](docs/design.md#L822) · [Brief changes](docs/design.md#L849)
- **`egm-design-1-5` · Stacked jobs can lose their merge target.** When B merges into A in an A → B → C stack, C needs the branch that received B. The rule fetches the configured base branch and leaves the handling of B’s actual target unspecified. It also allows deletion of a parent with a final, unmerged child that can still realign. Record and use the actual merge target. Retain parent refs while a child still depends on them. [Base change](docs/design.md#L512) · [Stacked jobs](docs/design.md#L550)
- **`egm-design-1-6` · A new attempt can complete using stale agent output.** The workdir persists across runs, and `.pecore/output.json` sits outside the tree restored on rollback. A later attempt that writes no result can use a previous result. Give each attempt fresh output storage and require a fresh result after an output correction. [Content state](docs/design.md#L532) · [Turn completion](docs/design.md#L660) · [Agent output](docs/design.md#L693)
- **`egm-design-1-7` · A generic RPC error can be classified as an expired login.** The decision order treats JSON-RPC `-32000` as an auth signal before checking connector-specific structured errors. The spike observed auth messages with that code and left quota and rate-limit cases open. Require an auth-specific signal and use authoritative connector error data when available. [Open questions](docs/design.md#L109) · [Turn classification](docs/design.md#L652)
- **`egm-design-1-8` · Forge failures lack a consistent path to auth and network waits.** A nonzero probe becomes `unknown` and waits as `network`. The example delivery command treats a nonzero exit as `failed`. Define a failure classification for both and show how a recognized login failure or outage enters the appropriate wait. [Goal G7](docs/design.md#L70) · [Probe rules](docs/design.md#L281) · [Delivery example](docs/design.md#L312) · [Wait states](docs/design.md#L526)
- **`egm-design-1-9` · The budget rule leaves concurrent usage and intake turns unspecified.** Parallel attempts can each start with the same remaining budget. The orchestrator’s usage has no stated budget treatment, and resumed Claude usage combines side-model tokens before pricing. Specify allowed overshoot, how in-flight work and intake count, and how to price usage by model where relevant. [Budget scheduling](docs/design.md#L564) · [Usage](docs/design.md#L645) · [Orchestrator](docs/design.md#L702)
- **`egm-design-1-10` · A crash during ticket intake can lose or duplicate work.** The design records seen IDs without a durable handoff to the orchestrator. A crash before job creation can lose the ticket. Retrying an uncertain handoff can create duplicate jobs. Persist pending intake in the project database, link job creation to a stable intake ID, and define when PeCore acknowledges the ticket. [Project database](docs/design.md#L242) · [Chat storage](docs/design.md#L711) · [Source intake](docs/design.md#L720)
- **`egm-design-1-11` · Image orders have no defined path to the model.** G1 accepts an image, chat stores attachments beside `chats.db`, and the session interface accepts text. The protected orchestrator runs as a different OS user. Define how attachments reach the connector and what the GUI shows when the selected connector cannot consume them. [Goal G1](docs/design.md#L64) · [Session interface](docs/design.md#L610) · [Chat storage](docs/design.md#L711)
- **`egm-structural-1-1` · The decision history omits D9 and D26.** Protected mode moved from a per-project OS user choice to one shared user. Project and job deletion changed to leave forge branches and PRs or MRs in place. Record both changes and update the container alternative, which still says the user is chosen per project. Related findings `egm-design-1-12` and `egm-style-1-9`. [Concepts brief](docs/concepts-brief.md#L651) · [Deletion](docs/design.md#L85) · [Container alternative](docs/design.md#L785) · [Changes table](docs/design.md#L844)
- **`egm-structural-1-2` · The job-state diagram disagrees with the transition rules.** The diagram shows final outcomes below `paused` and omits `paused` → `waiting`, which the prose allows. Make the source and target of each transition explicit in the diagram or a table. [Job states](docs/design.md#L476) · [Play rule](docs/design.md#L502)
- **`egm-structural-1-3` · The storage alternative lacks a deciding trade-off.** State tables and audit entries can share one transaction, and both alternatives can use delivery probes. Explain which concrete benefit justifies keeping the event store. [Storage alternative](docs/design.md#L796)
- **`egm-style-1-1` · Local execution and network activity are described too broadly.** PeCore contacts ticket sources and forges, and its commands have network access. State which data and processes stay local. In the local-only journey, identify the local commit as the endpoint of the recipe. [Problem statement](docs/design.md#L60) · [Local-only journey](docs/design.md#L145) · [Sources](docs/design.md#L713)
- **`egm-style-1-2` · The quota goal overstates the evidence.** The spike observed quota metadata, the design describes an error shape from adapter code, and the test plan calls for synthetic coverage. The open questions say observed quota and rate-limit failures are still missing. Distinguish these forms of evidence. Name the two wait states and state what happens to unrecognized errors with a valid login. [Goal G7](docs/design.md#L70) · [Open questions](docs/design.md#L109) · [Usage and errors](docs/design.md#L651)
- **`egm-style-1-3` · The Claude Code MCP risk row overstates the verified path.** The spike verified the environment setting with `claude -p`. The open questions still call for checking the ACP adapter path. Name the completed check and the pending check separately. Related finding `egm-structural-1-5`. [Open ACP check](docs/design.md#L108) · [Connector setting](docs/design.md#L683) · [Risk statement](docs/design.md#L829) · [Spike evidence](docs/spikes/acp.md#L65)
- **`egm-style-1-5` · Window closing, job Stop and app Quit use overlapping wording.** Use the UI action names. Close Window keeps jobs running in the tray. Stop signals processes for the selected job. Quit signals all job processes. [Desktop behavior](docs/design.md#L37) · [Job controls](docs/design.md#L82) · [Process shutdown](docs/design.md#L199)
- **`egm-style-1-7` · The typecheck is credited with ruling out later test failures.** The recipe may still send lint and test failures to Builder. State that pre-build typecheck failures go back to Tests and that Builder can report a disputed test using `tests_disputed`. [Recipe edges](docs/design.md#L364) · [Recipe explanation](docs/design.md#L409)
- **`egm-style-1-8` · The crash recovery goal gives queued jobs a different outcome from the state rules.** G12 says all existing jobs become paused or final. Section 4.1 pauses jobs that were running or waiting. Define the rule for queued jobs and use it in the recovery criterion. [Goal G12](docs/design.md#L75) · [Job states](docs/design.md#L491)
- **`egm-style-1-10` · The tool comparison reads as a current conclusion without fresh evidence.** The document cites a comparison it says it has not reverified, then makes broad claims in two sections. Keep one dated, attributed comparison and state PeCore’s requirements directly. [Problem statement](docs/design.md#L47) · [Existing tools](docs/design.md#L810)

## Nits

- **`egm-style-1-11` · Session grouping makes an unconditional billing claim.** Session groups reuse conversation history. The Linux spike saw cache savings in one Claude Code setup while the cache lasted. Qualify the billing claim by harness and cache lifetime. [Session groups](docs/design.md#L401) · [Usage](docs/design.md#L647) · [Linux spike](docs/spikes/linux-harnesses.md)
- **`egm-style-1-12` · Alternatives obscure the consequences of the choices.** Replace generic loss statements with the concrete effect when there is one. Describe manual merging for jobs that deliver a PR or MR. Local-only jobs can end at a commit. [Scope alternatives](docs/design.md#L774) · [Adapter alternative](docs/design.md#L784)
- **`egm-style-1-13` · The login copy claim and identity fallback need narrower wording.** Attribute the observed token refresh behavior to the Claude Code test. State that a connector without an identity notification can define `identityCommand`. [Harness accounts](docs/design.md#L450)
