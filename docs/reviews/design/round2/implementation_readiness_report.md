# PeCore Implementation Readiness Review

**Result.** The plan fails the Implementation Readiness Standard. Several gates depend on later phases, and the implementation needs decisions on process startup, delivery recovery, persistence and the renderer API. Round 1 covers `docs/design.md` lines 854–1274. All three reviewers read the seven selected context files. The readiness and codebase reviewers applied the Implementation Readiness Standard. [Implementation plan](docs/design.md#L854)

## Blockers

- **`egm-implementation-readiness-1-1` · Phase 0 cannot close with the listed inputs.** Its protected-mode check requires the shipped Node and adapter setup scheduled in Phase 3. The phase lists no files while requiring recorded fixtures. The result also determines the runner interface. `Spawn` returns a numeric process group ID immediately, while the protected path learns a candidate ID from stderr after launch. Identify the exact early spike inputs and outputs. Decide how the runner reports readiness, persists the group ID, and handles stop, exit or restart before readiness. Record evidence for process cleanup and MCP exclusion through cross-user ACP. Related findings `egm-codebase-details-1-3` and `egm-implementation-readiness-1-8`. [Spawn interface](docs/design.md#L593) · [Process groups](docs/design.md#L870) · [Spike test](docs/design.md#L1013) · [Build order](docs/design.md#L1268) · [Existing spike](docs/spikes/acp.md#L63)
- **`egm-implementation-readiness-1-2` · Build gates depend on later phases.** Phase 1 validates templates introduced later. Phase 2 needs a local project before the project creation code arrives. Phase 3 has one Claude Code connector and a local project, while `feature` requires another provider and GitHub delivery. Phase 5 requires all GUI actions before Phase 6 adds chat and sharing. The `api/` and `packages/app` entries also overlap later routes and earlier resources. Assign a runnable entry point, named recipe or fixture, and pass criteria to each gate. Keep the full GUI and multi-provider checks after their prerequisites. Related findings `egm-codebase-details-1-1` and `egm-style-1-1`. [Feature recipe](docs/design.md#L336) · [Project defaults](docs/design.md#L1093) · [GUI goal](docs/design.md#L79) · [Build gates](docs/design.md#L1269)
- **`egm-implementation-readiness-1-3` · Delivery probes lose outcomes needed for safe recovery.** The push probe forces exit zero after `ls-remote` and emits a SHA only when it matches the job commit. A failed lookup can appear absent, and a differing branch head cannot reach the lease. Define distinct results for lookup failure, absent branch, matching SHA and differing SHA. Pass the observed head to the lease, and verify that an intervening remote update prevents the push. The repo creation probe also needs to verify initial branch publication. Verify recovery after interruption between creation and push. Related findings `egm-codebase-details-1-4` and `egm-style-1-2`. [Remote creation](docs/design.md#L243) · [Recovery rule](docs/design.md#L569) · [Push lease](docs/design.md#L873) · [Shipped probes](docs/design.md#L1233)
- **`egm-implementation-readiness-1-4` · The file list cannot serve as an exact write allowlist.** Package manifests, lockfile and package build entry points are missing from the inventory. The renderer shell, themes, fake forge and end-to-end projects lack exact source paths. Some test paths and file ownership by phase are also unspecified. List exact create and modify paths by phase, including test infrastructure. Reserve globs for generated output. Specify the adapter versions and shipped Node version needed to reproduce the build. Related finding `egm-codebase-details-1-8`. [Adapter build](docs/design.md#L882) · [Test infrastructure](docs/design.md#L1003) · [Root inventory](docs/design.md#L1023) · [Renderer inventory](docs/design.md#L1187)
- **`egm-implementation-readiness-1-5` · The renderer cannot use `/live` with the stated header requirement.** The browser WebSocket constructor cannot attach the required Bearer header, and preload exposes only the port and token. Choose the renderer transport and upgrade authentication. Specify `Host` and `Origin` rules for the packaged app, development app and CLI. Define typed operations and responses for wizard progress, cancellation and inline confirmation, usage, prerequisite rechecks, themes and normalized log history. Related finding `egm-codebase-details-1-7`. [Local API](docs/design.md#L949) · [WebSocket](docs/design.md#L975) · [Preload and renderer](docs/design.md#L1186) · [Wizard](docs/ui-design.md#L260) · [Usage and settings](docs/ui-design.md#L308)
- **`egm-codebase-details-1-2` · Protected repository setup grants broader write access than the design allows.** Recursive group-write includes `config`, `hooks/` and `info/`. The security section reserves those paths to the app user. The plan also assigns ownership changes to an app session that has yet to acquire the group. Define exact ownership and permissions per path and identify which changes require the admin operation. Verify a newly created protected project and an existing project converted in the same app session. [Repository access rule](docs/design.md#L729) · [Mode switch](docs/design.md#L865) · [Repository setup](docs/design.md#L871)
- **`egm-codebase-details-1-5` · The database model leaves required writes and restart state undefined.** Event payloads lack the identifiers for node runs, attempts and queue items. `job.created` omits title and branch, and `attempt.started` omits the node-run link and account used by usage accounting. The model leaves final node and outcome, pause reason, round extensions, queue cancellation and the chat’s ACP session ID unspecified. Define typed identifiers, column types and nullability, event payloads and their projection writes. Verify these values survive reopening the databases. Related finding `egm-implementation-readiness-1-6`. [Data model](docs/design.md#L887) · [Job states](docs/design.md#L502) · [Chat resume](docs/design.md#L1162) · [Inbox](docs/ui-design.md#L228)

Their envelopes lack the `at` field and the spike recorder writes stderr to a sidecar. The expected-output files are still to be created. Name the five assets and decide whether to normalize them in tests or migrate them. Assign each retained, changed or new fixture and expected file to its phase. Related finding `egm-style-1-8`. ## Major findings

- **`egm-implementation-readiness-1-7` · Confirmation storage and hash inputs are ambiguous.** Connectors are global and can require approval before any project exists. The queue and confirmed hashes sit in project databases. The API hashes the displayed subject, and the runner stores a hash derived from the subject before comparing it with a file hash. Choose the store owner, name each digest and define its canonical inputs. Run the same definition and script bytes that passed the check. Verify connector approval with zero projects and definition changes during confirmation and before execution. Related findings `egm-codebase-details-1-5` and `egm-style-1-3`. [Connector scope](docs/design.md#L678) · [Queue storage](docs/design.md#L916) · [Queue API](docs/design.md#L960) · [Confirmation runner](docs/design.md#L1098)
- **`egm-implementation-readiness-1-8` · The agent interface leaves raw logs without a path to the engine.** `Session.events` exposes normalized events. The ACP client emits raw JSON-RPC and stderr that the engine runner must persist. Specify the raw line channel, where redaction occurs and what a test must assert about the stored lines. The process readiness aspect of this finding is covered under `egm-implementation-readiness-1-1`. [Session interface](docs/design.md#L610) · [Raw logs](docs/design.md#L748) · [ACP client](docs/design.md#L1067) · [Agent runner](docs/design.md#L1127)
- **`egm-implementation-readiness-1-9` · Project creation lacks a durable wait, cancel and retry sequence.** The plan promises to undo earlier steps. The UI keeps a remote created on the forge and reports it after local undo. Define which local effects roll back, what the API reports about the retained remote, and how the setup record resumes inline approval or a partially completed remote operation after restart. Verify cancellation and retry at each boundary. Related findings `egm-codebase-details-1-4` and `egm-style-1-4`. [Project creation](docs/design.md#L986) · [Wizard](docs/ui-design.md#L260)
- **`egm-implementation-readiness-1-10` · macOS and connector gates need exact verification cases.** The Keychain spike used a password. The plan chooses an empty password, leaves refresh open and gives direct argument hooks a `~` path without an expansion rule. Define the resolved path and creation and unlock steps for first and later logins, including after logout. Set pass criteria for the macOS release gate and for opencode success and Codex usage across resumed turns in Phase 6. Distinguish recorded checks from pending checks for Claude permissions, Keychain behavior and GitLab flags. Related findings `egm-codebase-details-1-9` and `egm-style-1-6`. [Keychain choices](docs/design.md#L869) · [Connector questions](docs/design.md#L110) · [GitLab template](docs/design.md#L1236) · [Build order](docs/design.md#L1264) · [Keychain spike](docs/spikes/macos-keychain.md#L29)
- **`egm-codebase-details-1-10` · The new-project wizard has conflicting navigation requirements.** The implementation and UI page lists include Logins. The UI’s explicit step removes the page and points to Settings > Accounts. Use one page list and align the cancellation behavior and auth links with it. Related finding `egm-style-1-5`. [Wizard files](docs/design.md#L1201) · [UI wizard](docs/ui-design.md#L260) · [Auth wait UI](docs/ui-design.md#L373)
- **`egm-style-1-7` · Main and engine ownership is unclear during startup and shutdown.** The quit sequence asks the engine to remove Compose projects. Section 4.9 assigns that work to Electron main. Name a single cleanup owner and define what main does if shutdown times out. Name the component that writes `run/api.json` consistently in the process and API plans. [Service shutdown](docs/design.md#L582) · [Quit sequence](docs/design.md#L984) · [Engine startup](docs/design.md#L1085) · [API server](docs/design.md#L1150)
